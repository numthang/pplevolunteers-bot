## ขั้นตอน

### 0. push ก่อน — `deploy.sh --production` ใช้ `git reset --hard origin/master`
```bash
git push origin master
```

### 1. สำรอง prod (ทำเสมอ)
```bash
sudo -u www bash -c 'cd /www/wwwroot/pple-volunteers && set -a && . ./.env && set +a && \
  PGPASSWORD="$DB_PASS" pg_dump -h "$DB_HOST" -U "$DB_USER" -d "$DB_NAME" -t "kanban_*" \
  > /tmp/kanban-before-20260819.sql && ls -la /tmp/kanban-before-20260819.sql'
```

### 2. TRUNCATE การ์ด — **ก่อน** DDL
```bash
sudo -u www psql -d pple_volunteers -c 'TRUNCATE kanban_cards RESTART IDENTITY CASCADE'
```

### 3. รัน DDL ที่ค้าง (27 statement · ห่อ BEGIN/COMMIT · รันซ้ำได้)
```bash
sudo -u www psql -d pple_volunteers -v ON_ERROR_STOP=1 \
  -f /www/wwwroot/pple-volunteers/scripts/migration/pending-2026-08-19.sql
```
ต้องจบด้วย `COMMIT` — ถ้า ERROR จะ rollback ทั้งก้อน ไม่มีสถานะครึ่งๆ

**ซ้อมมาแล้ว:** clone schema ลงฐานจำลอง → truncate → รันไฟล์นี้ 2 รอบ ผ่านทั้งคู่
ผลลัพธ์: เหลือตาราง kanban 6 ตัว (ไม่มี `kanban_labels`/`kanban_card_labels`) · `blocked` หายเกลี้ยง

### 4. deploy โค้ด — **บอทกับเว็บพร้อมกัน ห้าม --bot-only**
```bash
./deploy.sh --production
```

### 5. ~~ส่งไฟล์ import ขึ้น prod~~ — ไม่ต้องแล้ว
`scripts/import/kanban_import.xlsx` ติดไปกับ git → ขั้นที่ 4 พามาให้เรียบร้อยแล้ว

### 6. สร้าง people-map **จาก users ของ prod** แล้วเปิดตรวจ
```bash

```
เติม `users.id` ที่ยังว่าง · `null` = ข้าม (การ์ดไม่มีเจ้าภาพ ไปกองรอทำ)

### 7. import
```bash
# ⚠️ เช็ค org id ของ "อาสาประชาชน" บน prod ก่อน — dev เป็น 1 แต่ prod อาจไม่ใช่
sudo -u www psql -d pple_volunteers -c 'SELECT id, name FROM orgs ORDER BY id'

cd /www/wwwroot/pple-volunteers
sudo -u www node --env-file=.env scripts/import/kanbanFromAppflowy.mjs --all --org <ID>          # dry-run
sudo -u www node --env-file=.env scripts/import/kanbanFromAppflowy.mjs --all --org <ID> --commit
```
