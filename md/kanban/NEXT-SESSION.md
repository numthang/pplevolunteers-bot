## ⚠️ กับดักตอน deploy — อ่านก่อนรัน migration บน prod

1. **`ALTER TABLE kanban_card_checklist ALTER COLUMN field_id SET NOT NULL` จะพังถ้า prod มีข้อมูลเช็คลิสต์อยู่**
   บน dev ตอนแปลงมี 0 แถวเลยผ่านฉลุย · **ต้องเช็คก่อน:** `SELECT count(*) FROM kanban_card_checklist;`
   ถ้ามีแถว ต้องตัดสินใจก่อนว่าจะยกไป field ไหน (สร้าง field ชนิด checklist ให้ org แล้ว UPDATE ใส่ `field_id`)

   ถ้าเว็บขึ้นก่อนบอท (หรือกลับกัน) โดยยังไม่รัน migration = พังทั้งคู่

## งานที่เหลือ เรียงตามที่ควรทำ

### 1. ให้ user กดจริงก่อน (ยังไม่เคยกดเอง)
Claude เทสด้วย Playwright ผ่านหมดแล้ว แต่ **user ยังไม่เคยกดด้วยมือตัวเอง** — กฎบ้านนี้คือ
"ทำไปเทสไป · user กด 2 ทีเจอบั๊กที่เทสอัตโนมัติหาไม่เจอ" → รอผลก่อนค่อยไปต่อ

ให้ลองตามนี้ (dev server `localhost:3000`):
- เปิดการ์ด → กล่อง **"ข้อมูลของทีม"** → `+ เพิ่มช่องข้อมูล` → ลองครบทั้ง 8 ชนิด
- multi_select: เปิดกล่อง → พิมพ์ชื่อใหม่สร้างตัวเลือก → กด "..." เปลี่ยนชื่อ/สี/ลบ → ลากสลับลำดับ
- checklist: เพิ่มรายการ → ติ๊ก → ดู % ขยับ → ลากสลับ → ปิดการ์ดดูป้าย x/y บนหน้ารายการ
- **ลองบนมือถือจริงด้วย** (จอ ~390px)

### 2. 🔴 บั๊กเดิม: เช็คบ็อกซ์ "ติดปัญหาอยู่" ไม่เคยเซฟติดเลย
บั๊กตั้งแต่ก้อน 1 ไม่เกี่ยวกับ custom field — เจอตอนเทสรอบนี้

`CardModal.patch({ blocked })` **ไม่ส่ง `lockToken`** แต่ `/api/kanban/cards/[id]` PATCH
เส้น `blocked`/`blockedReason` ตกไปอยู่สาขา "autosave เนื้อหา" ที่บังคับเทียบ `lockToken` เสมอ
→ `undefined !== token จริง` ชนทุกครั้ง = ตอบ 409 "มีคนแก้การบ้านใบนี้ไปแล้ว" ทั้งที่ไม่มีใครแก้

**2 ทางเลือก:** ให้ `patch()` แนบ `lockToken.current` เมื่อ body มี `blocked` · หรือย้าย `blocked`
ไปเป็น action แยกไม่ผ่าน lockToken เหมือน `statusType` (แนะนำทางหลัง — ธงติ๊กเดียวไม่ใช่ autosave ช่องพิมพ์)

### 3. 🟡 ตัดสินใจ: ยุบป้ายเข้า custom field ไหม
**ยังไม่ได้เคาะ** — Opus เสนอ 3 ทาง user ยังไม่ตอบ

ข้อมูลจริงที่รออยู่: **3 กลุ่ม → 3 field · 29 ป้าย → options · 84 เส้น → ค่า** (`INSERT…SELECT` ล้วน)

โครงสร้างเหมือนกันแล้ว (กลุ่ม=field · ป้าย=options) แต่ **ยุบวันนี้จะเสีย 3 อย่างที่ป้ายทำอยู่แต่ field ยังทำไม่ได้:**

| ป้ายทำได้ | field ทำได้ไหม |
|---|---|
| กรองบนหน้า `/kanban` (OR ในกลุ่ม · AND ข้ามกลุ่ม · `lib/kanbanLabelFilter.js` + เทส 19 ข้อ) | ❌ ไม่มีเลย |
| ชิปโชว์บนแถวการ์ดในกระดาน (`LabelChips.jsx`) | ❌ ตั้งใจไม่ทำ ("การ์ดจะบวม") |
| rename/ซ่อน = สิทธิ์ admin เท่านั้น | ❌ ตัด admin gate ทิ้งไปแล้ว (ทุกคนแก้ได้) |

**ปมที่ต้องเคาะ:** แผนเดิมข้อ 3 เขียนว่า *"LabelManager → รวมเข้า `/kanban/fields`"* แต่หน้านั้นถูกลบไปแล้ว
→ ถ้ายุบป้ายเข้ามา ป้ายจะเสียการคุมระดับ admin ทันที ทั้งที่ org มี 7,376 คน และป้ายลบไม่ได้

- **(ก) ยังไม่ยุบ** — ทำ filter + ชิปบนแถวการ์ดให้ field ก่อน ค่อยยุบรอบหน้า ← **Opus เชียร์ทางนี้**
- **(ข) ยุบเลย** ยอมเสีย filter ชั่วคราว
- **(ค) ยุบ + คืน admin gate เฉพาะ field ที่ migrate มา** (มี 2 มาตรฐานในระบบเดียว)

### 4. ⬜ ขั้น 4 ของแผนเดิม — importer เก็บของที่เคยทิ้ง
`scripts/import/kanbanFromAppflowy.mjs` ข้าม 3 คอลัมน์**แบบเงียบๆ ไม่มีบรรทัดเตือน**
→ import 50 ใบที่จบแล้วรอบหน้าจะหาย **5 Discord + 31 FB**

- `Discord` → `source_url` (คอลัมน์พร้อมแล้ว)
- `FB Post` → field ชนิด url · `งบประมาณ` → field ชนิด number (กลไกพร้อมแล้ว เหลือสร้าง field + map)
- ต้องขึ้นสรุปตอนจบว่าเขียนลง field อะไรไปกี่ค่า · **dry-run ก่อน commit เสมอ**
