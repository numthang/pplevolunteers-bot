## ⚠️ กับดักตอน deploy — อ่านก่อนรัน migration บน prod

1. **`ALTER TABLE kanban_card_checklist ALTER COLUMN field_id SET NOT NULL` จะพังถ้า prod มีข้อมูลเช็คลิสต์อยู่**
   บน dev ตอนแปลงมี 0 แถวเลยผ่านฉลุย · **ต้องเช็คก่อน:** `SELECT count(*) FROM kanban_card_checklist;`
   ถ้ามีแถว ต้องตัดสินใจก่อนว่าจะยกไป field ไหน (สร้าง field ชนิด checklist ให้ org แล้ว UPDATE ใส่ `field_id`)
2. **บอทกับเว็บต้องขึ้นพร้อมกัน** — `db/kanbanCards.js` INSERT `source_url`/`source_message_id`
   ถ้าเว็บขึ้นก่อนบอท (หรือกลับกัน) โดยยังไม่รัน migration = พังทั้งคู่
3. migration ที่ค้างอยู่หลัง marker `-- production ทำถึงตรงนี้` มี **17 statement** (รวมของ orgchart 1 อันที่ไม่เกี่ยว kanban)

## งานที่เหลือ เรียงตามที่ควรทำ

### 1. ให้ user กดจริงก่อน (ยังไม่เคยกดเอง)
Claude เทสด้วย Playwright ผ่านหมดแล้ว แต่ **user ยังไม่เคยกดด้วยมือตัวเอง** — กฎบ้านนี้คือ
"ทำไปเทสไป · user กด 2 ทีเจอบั๊กที่เทสอัตโนมัติหาไม่เจอ" → รอผลก่อนค่อยไปต่อ

ให้ลองตามนี้ (dev server `localhost:3000`):
- เปิดการ์ด → กล่อง **"ข้อมูลของทีม"** → `+ เพิ่มช่องข้อมูล` → ลองครบทั้ง 8 ชนิด
- multi_select: เปิดกล่อง → พิมพ์ชื่อใหม่สร้างตัวเลือก → กด "..." เปลี่ยนชื่อ/สี/ลบ → ลากสลับลำดับ
- checklist: เพิ่มรายการ → ติ๊ก → ดู % ขยับ → ลากสลับ → ปิดการ์ดดูป้าย x/y บนหน้ารายการ
- **ลองบนมือถือจริงด้วย** (จอ ~390px)

### 2. 🔴 บั๊กเดิม: เช็คบ็อกซ์ "ติดปัญหาอยู่" ไม่เคยเซฟติดเลย
บั๊กตั้งแต่ก้อน 1 ไม่เกี่ยวกับ custom field — เจอตอนเทสรอบนี้

`CardModal.patch({ blocked })` **ไม่ส่ง `lockToken`** แต่ `/api/kanban/cards/[id]` PATCH
เส้น `blocked`/`blockedReason` ตกไปอยู่สาขา "autosave เนื้อหา" ที่บังคับเทียบ `lockToken` เสมอ
→ `undefined !== token จริง` ชนทุกครั้ง = ตอบ 409 "มีคนแก้การบ้านใบนี้ไปแล้ว" ทั้งที่ไม่มีใครแก้

**2 ทางเลือก:** ให้ `patch()` แนบ `lockToken.current` เมื่อ body มี `blocked` · หรือย้าย `blocked`
ไปเป็น action แยกไม่ผ่าน lockToken เหมือน `statusType` (แนะนำทางหลัง — ธงติ๊กเดียวไม่ใช่ autosave ช่องพิมพ์)

### 3. 🟡 ยุบป้ายเข้า custom field — **เคาะแล้ว 2026-08-18: ยุบได้ แต่ยังไม่ทำรอบนี้**

user บอก **`อำเภอ`/`category` กรองไม่บ่อย · `อุปกรณ์` ไม่กรองเลย** (อยากได้เป็นเช็คลิสต์เตรียมของแทน — ทำแล้ว ดูข้อ C)
→ เหตุผลเดียวที่ค้ำป้ายไว้คือ filter ซึ่งไม่ใช่ตัวค้ำอีกต่อไป · **เรื่องสิทธิ์ก็ไม่ใช่ปมแล้ว** (เคาะเส้นแบ่ง Notion ไปแล้ว)

**ยังไม่ทำเพราะเป็นก้อนใหญ่ที่แยกได้:** 13 touch points — `lib/kanbanLabelFilter.js` + เทส 19 ข้อ ·
`LabelChips.jsx` · `LabelManager.jsx` · `LabelPicker.jsx` · `/kanban/labels` · `db/kanban/labels.js` ฯลฯ
ข้อมูลจริงที่รอ: **3 กลุ่ม → 3 field · 29 ป้าย → options · 84 เส้น → ค่า** (`INSERT…SELECT` ล้วน)

⚠️ **ข้อนี้บล็อกข้อ 4 อยู่** — ต้องรู้ก่อนว่า `อำเภอ`/`category` ลงเป็นป้ายหรือ field แล้วค่อย import

### 4. ⬜ ขั้น 4 ของแผนเดิม — importer เก็บของที่เคยทิ้ง

> **เคาะ 2026-08-18: ยังไม่ทำตอนนี้ — รอ custom field นิ่งก่อน แล้ว import รอบเดียวจบทั้ง 82 ใบ**
> เหตุผล: ข้อ 3 (ยุบป้ายไหม) เป็นตัวตัดสินว่า `อำเภอ`/`category`/`อุปกรณ์` เข้าเป็น **ป้าย** หรือ **field**
> import ก่อนเคาะ = ต้องย้ายข้อมูล 84 เส้นทีหลังอยู่ดี · **ข้อ 3 บล็อกข้อ 4 อยู่**

**ตัวเลขที่ยืนยันแล้ว (นับจากไฟล์จริง 2026-08-18) — ไม่ใช่บั๊ก แต่ตั้งใจข้าม:**

| | จำนวน |
|---|---|
| แถวใน `backups/kanban/kanban_import.xlsx` | 83 (มี Title จริง **82**) |
| `เสร็จแล้ว` — ยังไม่เคยนำเข้า | **50** |
| ยังไม่จบ (`LIVE`) — นำเข้าไปแล้ว | **32** |
| `kanban_cards` ใน DB ตอนนี้ | **37** (32 จาก import + **5 สร้างด้วยมือ**) |

`kanbanFromAppflowy.mjs:198` กรอง `LIVE` เป็นค่าตั้งต้น · flag `--all` มีอยู่แล้วแต่ **ยังใช้ไม่ได้** (ดูข้อ 1 ล่าง)

**ของที่ 50 ใบจะเติมเข้ามา:** อำเภอ 33 · FB Post 31 · งบประมาณ 10 · Discord 5
(32 ใบเดิมก็ยังขาด FB Post 2 / งบ 3 / Discord 1 → ทำรอบเดียวได้ครบกว่า)

**⚠️ 3 อย่างที่ต้องเคลียร์ก่อนรัน import รอบใหม่:**

1. **ตัวซ้ำ — สคริปต์ไม่มี dedupe เลย** รัน `--all` วันนี้ = ได้ 82 ใบทับของเดิม 32 ใบ
   ถ้าจะ "ล้างแล้วเข้าใหม่" ต้องแยก **5 ใบที่สร้างด้วยมือ** ออกก่อน (ลบยกกระดานไม่ได้)
2. **ของที่แก้ด้วยมือหลัง import** — 32 ใบเดิมอาจถูกย้ายสถานะ/เพิ่มคอมเมนต์/ตั้งเจ้าภาพไปแล้ว
   ล้างทิ้ง = หายหมด · **ต้องเช็คก่อนตัดสินใจ ว่าจะ wipe+reimport หรือ merge ทีละใบ**
3. **`Checklist` กู้ไม่ได้ ไม่ต้องรอ custom field** — xlsx เก็บมาเป็นตัวเลข % (`0.73`) ไม่มีตัวข้อความ
   ข้อมูลหายตั้งแต่ต้นทาง AppFlowy (14 ใบใน 50 ที่จบ / 21 ใบใน 82)

`scripts/import/kanbanFromAppflowy.mjs` ข้าม 3 คอลัมน์**แบบเงียบๆ ไม่มีบรรทัดเตือน**
→ import 50 ใบที่จบแล้วรอบหน้าจะหาย **5 Discord + 31 FB**

- `Discord` → `source_url` (คอลัมน์พร้อมแล้ว)
- `FB Post` → field ชนิด url · `งบประมาณ` → field ชนิด number (กลไกพร้อมแล้ว เหลือสร้าง field + map)
- ต้องขึ้นสรุปตอนจบว่าเขียนลง field อะไรไปกี่ค่า · **dry-run ก่อน commit เสมอ**
