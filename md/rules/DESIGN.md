# Design Rules — กฎการออกแบบหน้าจอ (ทั้งโปรเจกต์)

> **ไฟล์นี้คือที่เดียวของกฎหน้าตาทั้งหมด** — ทั้ง "วางตรงไหน ทำไม" (ส่วนที่ 1) และ "ใช้คลาสอะไร"
> (ส่วนที่ 2 · สี · dark mode · type scale · ความกว้าง · มือถือ · component patterns)
> **ห้ามลอกกฎพวกนี้ไปเขียนซ้ำที่อื่น** จะกลายเป็นกฎสองชุดที่เพี้ยนกันเอง
>
> เขียน 2026-09-19 เพราะ user ต้องมาทักเรื่องเดิมซ้ำทุกโซนใหม่ ("เอาถังขยะไว้บนขวา" · "อย่าให้มันเบียดเนื้อหา" ·
> "เอาสถานะไปเบียดรายละเอียด") — ทุกข้อข้างล่างมาจากของจริงที่เคยผิดมาแล้ว ไม่ใช่ทฤษฎี

---

## 0. หลักการ 5 ข้อ (ที่เหลือคือรายละเอียดของ 5 ข้อนี้)

1. **เนื้อหาได้ความกว้างก่อน ปุ่มได้ทีหลัง** — ชื่อ/ยอดเงิน/รายละเอียดต้องไม่ถูกบีบเพราะมีปุ่ม
2. **ของที่ใช้นานๆ ครั้งให้ซ่อน ของที่ใช้บ่อยให้เห็น** — ลบ/เก็บเข้ากรุ = ซ่อนจน hover · เปิดดู/กดทำงาน = เห็นตลอด
3. **ซ่อนได้เฉพาะที่ที่ hover มีจริง** — จอสัมผัสไม่มี hover ห้ามให้ปุ่มโปร่งใสแต่ยังกดโดน
4. **ตำแหน่งเดียวกันทั้งแอพ** — ผู้ใช้ไม่ควรต้องหาว่าปุ่มลบของหน้านี้อยู่ไหน
5. **ป้าย/สถานะต้องไปอยู่บรรทัดที่มีที่ว่าง** ไม่ใช่แย่งบรรทัดกับชื่อ

## 0.5 พจนานุกรมคำสั่งของ user — คำไหนแปลว่าอะไร (อ่านก่อนตีความคำสั่ง UI)

> จดไว้ 2026-09-19 เพราะงานเดียว (ย้ายป้ายสถานะ) วนกันไป **4 รอบ** เพราะแปลคำว่า "หน้า/หลัง" ผิด
> user: *"บอกว่าไว้หลัง คือต่อท้ายเลย ไม่ใช่ข้างใต้ 555555"* — คำพวกนี้ไม่กำกวมสำหรับ user
> มันกำกวมสำหรับ Claude เท่านั้น **ถ้าไม่แน่ใจ ให้ถามก่อนลงมือ ถูกกว่าทำผิดแล้วรื้อ**

### ตำแหน่ง — "หน้า/หลัง" คือแกนนอน · "บน/ใต้" คือแกนตั้ง

| user พูดว่า | แปลว่า | ไม่ใช่ |
|---|---|---|
| **"ไว้หน้า X"** | ต่อ**หน้า** X **ในบรรทัดเดียวกัน** (inline ก่อน X) | ❌ บรรทัดเหนือ X |
| **"ไว้หลัง X" · "ต่อท้าย X"** | ต่อ**ท้าย** X **ในบรรทัดเดียวกัน** (inline หลัง X) | ❌ บรรทัดใต้ X |
| **"ข้างใต้ X" · "ใต้ X"** | บรรทัดใหม่ **ใต้** X | ❌ ต่อท้ายบรรทัดเดิม |
| **"ข้างบน X" · "เหนือ X"** | บรรทัดใหม่ **เหนือ** X | — |
| **"บนขวา" · "มุมขวาบน"** | `absolute` เกาะมุมกล่อง | ❌ ท้ายแถว flex (นั่นคือ "ขวาสุดของแถว") |
| **"ท้ายแถว"** | ปลายขวาของแถวเดียวกัน (`justify-between`) | — |

> 🔑 **กฎจำง่าย: หน้า/หลัง = แกนนอน (บรรทัดเดิม) · บน/ใต้ = แกนตั้ง (บรรทัดใหม่)**

### คำอธิบายอาการ

| user พูดว่า | แปลว่า | ต้องทำอะไร |
|---|---|---|
| **"เบียด"** | ของชิ้นนี้ไป**กินความกว้าง**ของเนื้อหา จนเนื้อหาถูกบีบ/โดน truncate | เอาของออกจาก flow (`absolute`) หรือย้ายไปบรรทัดที่มีที่ว่าง — **ไม่ใช่แค่เพิ่ม gap** |
| **"กินเนื้อที่ให้น้อยที่สุด"** | ห้ามเพิ่ม**ทั้งความกว้างและความสูง** | บรรทัดใหม่ก็ถือว่ากินเนื้อที่ (การ์ดสูงขึ้นทุกใบ) |
| **"ลองดู X"** (X = โซนอื่นในโปรเจกต์) | ไปดูว่า X แก้ปัญหานี้ยังไง แล้วเอาท่านั้นมา | ⚠️ **ตรวจก่อนลอก** — ถ้า X มีบั๊ก ให้เอา*เจตนา*มา ไม่ใช่ลอกบั๊กมาด้วย แล้วบอก user ว่าต่างตรงไหน |
| **"…ได้ไหม"** + กริยาลงมือ ("เอา…มาไว้", "ทำ…ให้หน่อย") | **สั่งให้ทำ** | ทำเลย |
| **"ดีไหม · คุ้มไหม · ควรทำไหม · ดีกว่าไหม"** | **ถามความเห็น** | ⛔ ห้ามแตะไฟล์ — วัด/วิเคราะห์แล้วตอบพร้อมตัวเลข จบด้วย "ทำเลยไหม" (CLAUDE.md §Preferences) |

### ร่องรอยจริงของวันที่ 2026-09-19 (เก็บไว้เป็นตัวอย่าง อย่าลบ)

| # | user พูด | Claude ทำ | ผล |
|---|---|---|---|
| 1 | "เอาถังขยะมาไว้บนขวา เวลา hover ได้ไหม ลองดู kanban" | ย้ายถังขยะเป็น `absolute` มุมขวาบน + ใส่ `pr-10` ให้บรรทัดชื่อ | ⚠️ ถูกครึ่งเดียว — `pr` ไปเบียดชื่อ |
| 2 | "อย่าให้มันเบียดเนื้อหาใน card เลยได้ไหม" | ตัด `pr` ออกในจอที่ hover ได้ | ✅ |
| 3 | "สถานะเอาไปไว้**หน้า** title" | เข้าใจผิดเป็น "บรรทัดเหนือ title" | ❌ รอบที่ 1 ของการแปลผิด |
| 4 | "**หน้า** title ไม่ใช่**บน** title" | ย้ายเป็น inline ก่อนชื่อ | ✅ ตรงคำ แต่ยังกินความกว้างชื่อ |
| 5 | "ย้ายไปไว้ท้ายสุด**หลัง**จำนวนเงินเลยดีกว่า" | เข้าใจผิดเป็น "บรรทัดใต้ยอดเงิน" | ❌ รอบที่ 2 ของการแปลผิด |
| 6 | "บอกว่าไว้**หลัง** คือ**ต่อท้าย**เลย ไม่ใช่**ข้างใต้** 555555" | ต่อท้ายบรรทัดยอดเงิน inline | ✅ จบ |

**บทเรียน:** รอบ 3 กับ 5 คือคำเดียวกันที่แปลผิดซ้ำ — เสียไป 2 รอบเต็ม
ทั้งที่ต้นทุนของการถาม *"หมายถึง inline ต่อท้ายบรรทัดเดิม หรือขึ้นบรรทัดใหม่ใต้มัน?"* คือประโยคเดียว

## 1. กายวิภาคของการ์ด (card anatomy) — ลำดับตายตัว

```
┌────────────────────────────────────────────────┐
│ [รูป/ไอคอน]  ชื่อเรื่อง (truncate)        [🗑] │ ← ชื่อได้ความกว้างเต็ม ปุ่มลอยทับ
│              รายละเอียดรอง                      │
│              ยอด/จำนวน/เวลา  (ป้ายสถานะ)        │ ← ป้ายต่อท้ายบรรทัดตัวเลข
└────────────────────────────────────────────────┘
```

| บรรทัด | ใส่อะไร |
|---|---|
| 1 | **ชื่อเรื่องอย่างเดียว** `truncate` / `line-clamp-2` |
| 2 | ที่มา · เจ้าของ · จังหวัด |
| 3 | ยอด · จำนวน · เวลา **+ ป้ายสถานะต่อท้ายในบรรทัดเดียวกัน** |

### ⛔ ป้ายสถานะไปเกาะ "บรรทัดที่สั้นที่สุด" ไม่ใช่บรรทัดชื่อ และไม่ใช่บรรทัดของตัวเอง

```jsx
<p className="text-base font-semibold … truncate pr-10 [@media(hover:hover)]:pr-0">{title}</p>
<p className="text-sm …">{subtitle}</p>
<p className="text-sm … mt-0.5">
  {amountLine}
  <span className={`inline-block align-middle ml-1.5 px-2.5 py-0.5 text-sm font-medium rounded-full ${TONE_CLS[stage.tone]}`}>
    {stageLabel}
  </span>
</p>
```

**วิธีเลือกที่วางป้าย:** หาบรรทัดที่เนื้อหา**สั้นและความยาวคาดเดาได้** ("2 คน · 800 บาท", "3 วันที่แล้ว")
แล้วเอาป้ายต่อท้ายบรรทัดนั้น — ป้ายได้ที่ว่างที่ไม่มีใครใช้อยู่แล้ว โดยไม่กินความสูงเพิ่มสักพิกเซล

ลองมาแล้ว 4 ท่าในวันเดียว (2026-09-19) — **ต่อท้ายบรรทัดตัวเลขชนะ**:

| ท่า | ผลจริงที่ 375px |
|---|---|
| ป้ายท้ายแถวเดียวกับชื่อ (`justify-between`) | ❌ ป้ายจองความกว้างก่อน ชื่อเหลือ ~100px โดน truncate แทบทุกใบ |
| ป้ายหน้าชื่อ บรรทัดเดียวกัน | ❌ ดีขึ้นเป็น ~155px แต่ยังกินของชื่อ + ตาต้องข้ามป้ายก่อนถึงจะอ่านชื่อ |
| ป้ายบรรทัดของตัวเอง ใต้ยอดเงิน | ⚠️ ชื่อรอด แต่การ์ดสูงขึ้น 1 บรรทัดทุกใบ เห็นการ์ดต่อหน้าจอน้อยลงจริง |
| **ป้ายต่อท้ายบรรทัดยอดเงิน** | ✅ ชื่อได้เต็ม · ความสูงเท่าเดิม · ป้ายไปนั่งที่ว่างที่ไม่มีใครใช้ |

⛔ **บรรทัดที่มีป้ายห้ามใส่ `truncate`** — ป้ายยาวเกินต้อง**ตกบรรทัดใหม่เอง** ดีกว่าโดนตัดจนอ่านไม่ออก
(คนละกฎกับบรรทัดชื่อที่ต้อง truncate — ชื่อยาวเดาต่อได้ สถานะเดาไม่ได้)

ตัวอย่างจริง: `web/app/finance/payouts/page.js`

## 2. ปุ่มโผล่ตอน hover (hover-reveal) — ท่ามาตรฐานท่าเดียว

**ใช้กับ:** ลบ · เปลี่ยนชื่อ · เมนู `⋯` · เก็บเข้ากรุ — คือของที่ใช้นานๆ ครั้งและพลาดแล้วเจ็บ
**ห้ามใช้กับ:** ปุ่มที่เป็นงานหลักของการ์ด (เปิด · รับงาน · โทร · จ่าย) — พวกนี้เห็นตลอด

```jsx
{/* การ์ด */}
<div className="group relative … ">

  {/* ปุ่มลอยมุมขวาบน — absolute จึงไม่กินความกว้างของเนื้อหาเลย */}
  <button
    aria-label={t('…')} title={t('…')}
    className="absolute top-1.5 right-1.5 h-8 w-8 shrink-0 flex items-center justify-center rounded-lg transition
      bg-card-bg text-warm-400 dark:text-disc-muted hover:text-red-500 hover:bg-red-50 dark:hover:bg-disc-hover
      opacity-100 [@media(hover:hover)]:opacity-0 [@media(hover:hover)]:group-hover:opacity-100 [@media(hover:hover)]:focus:opacity-100"
  >
    <Trash2 size={16} />
  </button>
</div>
```

**กติกา 4 ข้อของท่านี้:**

1. ⛔ **การ์ดเดี่ยว = `absolute` เท่านั้น ห้ามเป็นลูกในแถว flex** — ปุ่มที่อยู่ในแถวกินความกว้างถาวร
   แม้ตอนมองไม่เห็น = "เบียดเนื้อหา" (user ทัก 2026-09-19) · ถ้าเนื้อหาอาจมุดใต้ปุ่ม ให้ `pr-10`
   **เฉพาะบรรทัดที่ชนจริง** และถ้าเผื่อไว้ให้ปุ่มที่โชว์ถาวรบนมือถือ ให้ปลดออกด้วย `[@media(hover:hover)]:pr-0`

   ✅ **ข้อยกเว้น: แถวในตาราง/รายการที่ต้องเรียงคอลัมน์ตรงกัน** — ให้ปุ่มอยู่ใน flow ได้ (ซ่อนด้วย `opacity`
   เฉยๆ ไม่ต้อง absolute) เพราะที่ว่างเท่ากันทุกแถวคือสิ่งที่ต้องการ ไม่ใช่ของเสีย · เส้นแบ่งคือ
   **"จองที่เท่ากันทุกแถว" (โอเค) vs "แย่งที่จากเนื้อหาแถวนั้น" (ไม่โอเค)**
   ตัวอย่าง: `web/app/finance/payouts/[id]/page.js` แถวรายชื่อผู้รับเงิน

   ⛔ **ปุ่มที่โผล่เป็นบางแถว (ตามเงื่อนไขข้อมูล) ต้องอยู่ท้ายสุดของแถวเสมอ** — ถ้าอยู่กลางแถว
   พอเงื่อนไขเปลี่ยน (ติ๊ก "จ่ายแล้ว") ปุ่มโผล่มาดันของที่เหลือเลื่อนทั้งแถว แถวแต่ละแถวเลยไม่ตรงคอลัมน์กัน
   (user ทัก 2026-09-19 "กระดิ่งอ่ะ มันเกะกะ content")
2. ⛔ **ต้องครอบ `[@media(hover:hover)]:` ไม่ใช่ `sm:`** — `sm:` วัดความกว้างจอ ไม่ได้วัดว่า hover ได้
   iPad แนวนอน/จอสัมผัสใหญ่กว้างเกิน `sm` แต่ hover ไม่ได้ → ได้ปุ่มโปร่งใสที่กดโดนโดยไม่ตั้งใจ
   (dead zone มุมขวาบนของการ์ด — เคยเกิดจริงที่ `PostsHome.jsx` ก่อนแก้)
   **มือถือ = โชว์ถาวร** (`opacity-100` เป็นค่าตั้งต้น แล้วค่อยซ่อนในอุปกรณ์ที่ hover ได้)
3. ✅ **ต้องมี `bg-card-bg`** — ตอน fade in ทับข้อความ ถ้าไม่มีพื้นหลังจะอ่านเป็นตัวหนังสือซ้อนกัน
4. ✅ **ต้องมี `focus:opacity-100`** (หรือ `focus-within` ถ้าเป็นกลุ่มปุ่ม) — ไม่งั้นคนกด Tab หาปุ่มไม่เจอ

**ตำแหน่ง = มุมขวาบนของการ์ดเสมอ** · หลายปุ่มให้รวมเป็นกลุ่ม `flex items-center gap-0.5` ที่มุมเดียวกัน
(เรียงจากใช้บ่อย → อันตราย ซ้ายไปขวา) · เกิน 3 ปุ่มให้ยุบเป็นเมนู `⋯`

## 3. ปุ่มทำลาย (ลบ / ปิดรอบ / ยกเลิก)

- สีปกติ **เทา** (`text-warm-400 dark:text-disc-muted`) → **แดงตอน hover** เท่านั้น
  ⛔ ห้ามแดงตั้งแต่ยังไม่แตะ — การ์ด 20 ใบเป็นถังขยะแดง 20 อันคือหน้าจอที่ตะโกนใส่คนใช้
- ต้องมี `confirm()` (หรือโมดัลยืนยัน) เสมอ · ข้อความยืนยันต้องบอก **ชื่อของที่จะหาย**
- ของที่ล็อกแล้ว **ให้ปุ่มหายไปเลย ไม่ใช่ disabled** ถ้าเงื่อนไขอธิบายยาก
  (เช่น รอบจ่ายที่ `status === 'paid'` — ปิดแล้วย้อนไม่ได้)
- ลบแล้วกู้ไม่ได้ ≠ ลบแล้วเข้ากรุ — **ถ้ากู้ได้ให้ใช้คำว่า "เก็บเข้ากรุ" และไอคอน `Archive`** ไม่ใช่ถังขยะ

## 4. ปุ่มไอคอน — ขนาดกับพื้นที่แตะ

| ที่ใช้ | ขนาดกล่อง | ไอคอน |
|---|---|---|
| ปุ่มลอยบนการ์ด | `h-8 w-8` | `size={16}` |
| ปุ่มไอคอนในแถว/ทูลบาร์ | `h-9 w-9` | `size={16}` |
| ปุ่มปิดโมดัล | `h-9 w-9` | `size={20}` |

- **ทุกปุ่มไอคอนต้องมี `aria-label` + `title`** — ไม่มีข้อความกำกับ = คนใหม่เดาไม่ออก และ screen reader อ่านไม่ได้
- ปุ่มไอคอนในแถว flex ต้อง `shrink-0` เสมอ (ไม่งั้นโดนบีบจนไม่เป็นสี่เหลี่ยม — ดู §จอมือถือ ในส่วนที่ 2)
- อยู่ในการ์ดที่คลิกได้ทั้งใบ → `onClick={(e) => { e.stopPropagation(); … }}` **ทุกครั้ง**

## 5. ป้ายสถานะ (status badge)

## 8. แถวปุ่ม — บนมือถือต้อง fluid (เต็มความกว้าง เรียงลง)

> user ทัก 2026-09-19: *"ปุ่ม 4 ปุ่มด้านล่างทำให้มัน fluid เวลา mobile ได้ไหม"*
> §จอมือถือ (ส่วนที่ 2) เขียนกฎ "มือถือให้เต็มความกว้าง" ไว้แล้ว — ตรงนี้คือ**ท่าที่ใช้จริง**

```jsx
{/* ✅ มือถือ = grid 1 คอลัมน์ · จอกว้าง = แถวปกติ */}
<div className="mt-6 grid grid-cols-1 gap-2 sm:flex sm:flex-wrap">
  <button className={BTN2}>…</button>
  <button className={BTN2}>…</button>
  <button className={BTN}>…</button>
</div>
```

**ทำไมต้อง `grid grid-cols-1` ไม่ใช่ `flex-wrap` เฉยๆ**

| ท่า | ผลบนมือถือ |
|---|---|
| `flex flex-wrap gap-2` | ❌ ปุ่มกว้างตามความยาวข้อความ → แต่ละแถวกว้างไม่เท่ากัน ขอบขวาไม่ตรง ปุ่มสุดท้ายค้างครึ่งแถว |
| `flex flex-col` + `w-full sm:w-auto` ทุกปุ่ม | ⚠️ ได้ผลเหมือนกัน แต่ต้องไปเติมคลาสที่ปุ่มทุกตัว — ปุ่มพวกนี้มักเป็น `const BTN` ที่ใช้ร่วมกับโมดัล แก้ที่เดียวพังอีกที่ |
| **`grid grid-cols-1 gap-2 sm:flex sm:flex-wrap`** | ✅ ลูกของ grid ยืดเต็มคอลัมน์เอง **ไม่ต้องแตะคลาสปุ่มเลย** · `sm:flex` คืนพฤติกรรมเดิมบนจอกว้าง |

**กติกา:**
- ใช้กับ**ทุกแถวที่มีปุ่มข้อความตั้งแต่ 2 ปุ่มขึ้นไป** (แถบ action ท้ายหน้า · footer ของโมดัล · ฟอร์ม)
- **ปุ่มไอคอนล้วน (`h-9 w-9`) ไม่ต้อง fluid** — มันเป็นสี่เหลี่ยมจัตุรัสโดยตั้งใจ ยืดแล้วเพี้ยน
- ปุ่ม **2 ปุ่มสั้นๆ** (ยืนยัน/ยกเลิก) ใช้ `grid-cols-2` ได้ ถ้าข้อความสั้นจริง (≤ 8 ตัวอักษร)
- ถ้าปุ่มเยอะจนสูงเกินครึ่งจอ → ยุบตัวที่ใช้น้อยเป็นเมนู `⋯` ก่อน อย่าปล่อยให้เรียงลงมา 6 ปุ่ม
- `mobileAudit` เตือนเคสนี้ด้วยกฎ **`ragged`** (และ **`slack`** สำหรับแถวที่มีช่องกรอก)
  ทั้งคู่เป็นคำแนะนำ ไม่ทำให้ exit 1 → เจอที่แถวปุ่ม = แก้ ไม่ใช่ข้าม
  · **ปุ่มไอคอนล้วน (จัตุรัส) ถูกยกเว้นจากกฎ `ragged` แล้ว** ไม่ต้องมาสงสัยว่าทำไมไม่โดนเตือน
  · แถวตัวอย่างที่ตั้งใจให้ปุ่มกว้างตามข้อความ ให้ประกาศ `data-audit-ok="ragged"` พร้อมคอมเมนต์เหตุผล
- ✅ ใช้ `<ButtonRow>` จาก `components/ui/Button` แทนการเขียนคลาสเอง — ท่านี้ถูกห่อไว้ให้แล้ว

### ความกว้างของหน้า — ค่าเริ่มต้น 1024px · โซนไหนอยากเต็มจอให้ประกาศ `data-wide`

⛔ **`-mx-4` แหกกรอบไม่ได้** — negative margin หักล้างได้แค่ *padding* ของพ่อ ทะลุ `max-width` ไม่ได้
(นี่คือเหตุผลที่ `max-w-7xl` ใน `app/calling|posts|docs/layout.js` เป็น dead code มาตลอด — เจอ 2026-08-17)

**วิธีทำให้โซนเต็มจอ — เติมคำเดียวที่ layout ของโซน:**
```jsx
<div data-wide className="-mx-1 sm:-mx-4 -mt-3 min-h-screen bg-warm-50 dark:bg-disc-bg2">
```
`app/globals.css` มี 2 กฎที่เกาะ attribute นี้อยู่แล้ว → เนื้อหา **และ** แถบ nav ยืดตามเอง

| ตาราง/รายการหลายคอลัมน์ | 1280px — `data-wide` แล้วครอบ `max-w-7xl` ในหน้านั้นเอง |
| ฟอร์ม · ข้อความยาว · หน้าตั้งค่า | **ปล่อยค่าเริ่มต้น 1024px** (กว้างกว่านี้ตาต้องกวาดไกล อ่านยากกว่าเดิม) |

ตอนนี้ประกาศ `data-wide` แล้ว 2 โซน: `app/kanban/layout.js` · `app/team/layout.js`

### จอมือถือ — ออกแบบที่ **375px** เสมอ · ตรวจด้วยเครื่องก่อนส่งงาน

> เขียนกฎนี้ 2026-08-31 เพราะ user ต้องเป็นคนเปิดมือถือไปเจอเองทุกครั้งแล้วมาสั่งให้ไล่แก้
> (`12230e0 fix(team)`, `8408571 fix(case)`, `a97661d fix(kanban/board)` — reactive ทั้งหมด)
> เหตุผลเดียวกับ §Type scale: โซนใหม่เดาเอง แล้ว user รับบทเป็นคนตรวจ

⛔ **`html { font-size: 18px }`** (`app/globals.css:22`) — **ทุกคลาสที่เป็น rem ใหญ่กว่าที่เอกสาร Tailwind บอก 12.5%**
`w-64` = **288px ไม่ใช่ 256** · `w-52` = 234 · `p-4` = 18px · `max-w-5xl` = 1152px ไม่ใช่ 1024
(`sm:` `md:` เป็น media query หน่วย px จึงไม่โดนผลนี้) → **คำนวณความกว้างด้วยเลขจากเอกสาร Tailwind = ผิดทุกครั้ง**

**งบความกว้างจริง — ที่ 375px เหลือใช้ ~339px** (`main px-1` 9px + `px-3` ของ layout โซน 27px)
ในโมดัลเหลือ ~285px · ตัวเลขนี้คือเพดานจริง ไม่ใช่ 375

⛔ **กับดักที่ทำให้ "ดูแล้วไม่เห็นพัง" ทั้งที่พัง:** Chrome บนมือถือ **ถ่าง layout viewport เองเมื่อเนื้อหาล้น**
(เช่น 375 → 409) แล้วย่อทั้งหน้าลงให้พอดีแทนที่จะตัด → เปิด DevTools แล้วดูเผินๆ "ไม่มีอะไรล้น"
แต่ของจริงบนเครื่อง user คือ **ทั้งหน้าถูกย่อจนตัวหนังสือเล็ก + ปุ่มริมขวากดไม่ถึง**
→ ต้องวัดเทียบ **ความกว้างจอที่ตั้งใจ** เสมอ ห้ามเทียบ `window.innerWidth`

**ตรวจด้วยเครื่อง — บังคับก่อนบอกว่าเสร็จ:**
```bash
node scripts/dev/mobileAudit.mjs --routes /หน้าที่แก้     # exit 1 = ยังมีจุดล้น
node scripts/dev/mobileAudit.mjs --all                    # กวาดทุกโซน
```
หน้าที่มี dropdown/modal ต้องเพิ่ม `steps` ใน `scripts/dev/mobileAudit.routes.mjs` ก่อน ไม่งั้นตรวจไม่ถึง
สคริปต์ยังเตือน `slack · ไม่เต็มความกว้าง` ให้ด้วย (แถวที่มี select/input แล้วเหลือที่ว่างท้ายแถว > 32px)
— เป็นคำแนะนำ ไม่ทำให้ exit 1 แต่**บนมือถือค่าเริ่มต้นคือเต็มความกว้าง** ถ้าจงใจไม่เต็มให้เขียนเหตุผลกำกับในโค้ด

| ห้าม | ให้ทำแทน |
|---|---|
| แถวปุ่ม / segmented ยาวๆ ที่ไม่มีทางหนี | `flex-wrap` **หรือ** `<select>` ที่ `sm:hidden` คู่กับแถบปุ่ม `hidden sm:inline-flex` (ดู `Segmented` ใน `KanbanHome.jsx`) |
| `absolute` panel กว้างตายตัว (`w-64`, `w-72`) | เติม `max-w-[calc(100vw_-_1.5rem)]` เสมอ (⚠️ **ต้องมี `_` รอบ `-`** ไม่งั้น Tailwind ปล่อย `calc(100vw-1.5rem)` ที่ CSS ทิ้งทั้งบรรทัดแบบเงียบๆ) · หรือ `w-full` ในกล่อง `relative` (`TagCombobox.jsx`) |
| เมนูลอยเกาะปุ่มที่**ไม่ได้อยู่ริมขวาสุด**ของแถว | ให้กล่องครอบปุ่มเป็น `static sm:relative` แล้วให้แถวเป็น `relative` → มือถือเมนูเกาะขอบแถว จอกว้างเกาะปุ่มเหมือนเดิม (ดูเมนู "เรียงลำดับ" ใน `KanbanHome.jsx`) |
| ตัวควบคุมบนมือถือกว้างครึ่งๆ กลางๆ | **มือถือให้เต็มความกว้าง** — กล่องครอบ `w-full sm:w-auto` · `<select>`/ช่องค้นหา `flex-1 min-w-0` · ป้ายที่ไม่จำเป็น `hidden sm:inline` (ย้ายไป `aria-label` แทน) |
| กริดสองคอลัมน์ความกว้างตายตัวทุกจอ | `grid-cols-1 sm:grid-cols-[11rem_minmax(0,1fr)]` (`FieldRow.jsx:25`) |
| `p-6` / `px-6` ในโมดัล | `p-4 sm:p-6` — คืนพื้นที่ 16px ที่จอ 375 |
| `opacity-0 group-hover:opacity-100` เป็นทางเดียวที่เข้าถึงปุ่ม | `opacity-100 [@media(hover:hover)]:opacity-0 [@media(hover:hover)]:group-hover:opacity-100` — **จอสัมผัสไม่มี hover** (⛔ `sm:` ใช้ไม่ได้ วัดความกว้างจอ ไม่ได้วัด hover — iPad แนวนอนกว้างเกิน `sm` แต่ hover ไม่ได้) · ท่าเต็ม + เหตุผลอยู่ [md/rules/DESIGN.md §2](rules/DESIGN.md) |
| ปัดแนวนอน (`overflow-x-auto` เป็นทางแก้) | user เกลียดการปัด — ให้ซ้อนลงมาแล้วพับได้แทน (กระดาน kanban `flex-col … xl:grid`) |
| แถว flex ที่ลูกไม่มี `min-w-0` / ปุ่มไอคอนไม่มี `shrink-0` | ปุ่มไอคอน `h-9 w-9` ต้อง `shrink-0` เสมอ ไม่งั้นโดนบีบจนไม่เป็นสี่เหลี่ยม |

**ข้อความไทยหลอกตา:** เบราว์เซอร์หาจุดตัดบรรทัดตรงพยางค์ได้ (`"ยังไม่มีคน"` ตัดจาก `"ช่วย"`)
→ min-content แคบกว่าที่คิดมาก ข้อความสั้นๆ ก็ตกบรรทัดได้แม้จอกว้าง **ห้ามอนุมานจาก CSS เฉยๆ ต้องวัดจริง**

### Type scale — ใช้ 5 ขนาดนี้เท่านั้นทั้งโปรเจกต์

> เขียนกฎนี้ 2026-08-17 เพราะโซนใหม่ (kanban) เดาสเกลเองแล้วหลุดทั้งโซน — user ต้องมาไล่แก้ซ้ำทุกครั้งที่ทำแอพใหม่
> **ตัวเลขอ้างอิงของจริง:** `components/calling/` ใช้ `text-base` 74 จุด · `text-sm` 28 · `text-lg` 6 · `text-2xl` 5

| ใช้กับ | class |
|---|---|
| หัวหน้าเพจ (h1) | `text-2xl font-bold` |
| หัวข้อกอง / หัว modal (h2) | `text-lg font-medium` (กองในหน้า list ใช้ `font-semibold` ได้) |
| ชื่อการ์ด / หัวข้อย่อย (h3) | `text-base font-semibold` |
| **เนื้อความ · meta · ปุ่ม · input · ข้อความ error — ค่าเริ่มต้นของทุกอย่าง** | `text-base` |
| label ฟอร์ม · badge/chip · ตัวเลขกำกับ · hint | `text-sm` |

❌ **ห้ามใช้ `text-xs` และห้ามใช้ขนาดกำหนดเอง** (`text-[11px]`, `text-[13px]`) — เล็กสุดของโปรเจกต์คือ `text-sm`
❌ ห้ามใช้ `rounded-xl` กับการ์ด/กล่อง — การ์ดทั้งโปรเจกต์เป็น `rounded-lg`
❌ ปุ่มห้ามเป็น `px-3 py-1.5 text-sm` — ปุ่มมีขนาดเดียวคือ `px-4 py-2 text-base` (ดู §Primary button)
  **ข้อยกเว้นเดียว:** ปุ่มบนการ์ด `/kanban` (รับงาน/เอากลับจากกรุ/ลบถาวร) ใช้ `px-3 py-1.5 text-sm` (เคาะ 2026-09-02)
  — การ์ดแคบและมีปุ่มได้หลายอันพร้อมกัน ปุ่มมาตรฐานดันการ์ดสูงเกินไป ห้ามลอกไปใช้นอกการ์ด kanban
✅ ไอคอน `lucide-react` ใช้ `size={16}` เป็นค่าเริ่มต้น (18-20 เฉพาะปุ่มปิด/ไอคอนเดี่ยว)

**ก่อนเขียน component ใหม่:** เปิดไฟล์ใน `components/calling/` (เช่น `CampaignCard.jsx`, `SmsModal.jsx`) มาวางข้างจอแล้ว **ลอกคลาสมาตรงๆ** — ห้ามเขียนสเกลขึ้นเอง


### Component Patterns

#### Input / Select
```
h-11 px-3 text-base rounded-lg
border border-warm-200 dark:border-disc-border
bg-card-bg text-warm-900 dark:text-disc-text
placeholder-warm-400 dark:placeholder-disc-muted
focus:outline-none focus:ring-2 focus:ring-teal
```

#### Label
```
text-sm font-medium text-warm-700 dark:text-disc-muted mb-1
```

#### Textarea — **ต้องยืดตามข้อความเสมอ (fluid) ไม่มีข้อยกเว้น**
user ทักซ้ำหลายรอบ: กล่องข้อความความสูงตายตัวที่ต้องเลื่อน scroll ข้างในหรือลากมุมเอง = ผิดทั้งโปรเจกต์

```jsx
import useAutoGrow from '@/lib/useAutoGrow.js'

const ref = useAutoGrow(value)          // ← hook กลาง อย่าเขียนใหม่เอง
<textarea ref={ref} value={value} onChange={...}
  className="... resize-none overflow-hidden min-h-[140px]" />
```

- ❌ `rows={8}` + `style={{ resize: 'vertical' }}` เฉยๆ · ❌ `overflow-y-auto` ในกล่องพิมพ์
- ⚠️ ห้ามเรียก `autoGrow()` ซ้ำใน `onChange` — hook ทำให้แล้ว 1 ครั้งต่อ render · ใส่ซ้ำ = forced reflow 2 รอบต่อ 1 ตัวอักษร = พิมพ์สะดุดบนข้อความยาว
- ใช้แล้วที่: `components/case/CaseContentEditor.jsx`, `components/case/CaseManageActions.jsx` (`components/posts/PostEditor.jsx` มีสำเนาของตัวเองมาก่อน hook — ของใหม่ใช้ hook)

#### Card / Row item
```
border border-warm-200 dark:border-disc-border bg-card-bg
hover:bg-warm-50 dark:hover:bg-disc-hover
```

#### Primary button
```
bg-teal hover:opacity-90 text-white rounded-lg text-base font-medium px-4 py-2
```
> ⭐ **ของใหม่ให้ `import Button from '@/components/ui/Button'` แทนการลอกคลาส** (เพิ่ม 2026-09-19)
> คลาสข้างบนคือสิ่งที่ primitive ตัวนั้นใส่ให้ — เขียนไว้ที่นี่เพื่อให้รู้ว่าได้อะไร ไม่ใช่ให้ลอกไปแปะ
> ดูของจริงทุกชิ้นพร้อมกันที่ **`/styleguide`** · ทำไมต้องมี: วัด 2026-09-19 พบ `<button>` 714 ตัว
> แต่คลาส "rounded + px" ไม่ซ้ำกันถึง 92 แบบ เพราะแต่ละไฟล์ประกาศ `const BTN` ของตัวเอง

#### Secondary / Cancel button
```
border border-warm-200 dark:border-disc-border
text-warm-900 dark:text-disc-text
hover:bg-warm-50 dark:hover:bg-disc-hover
rounded-lg text-base font-medium px-4 py-2
```

#### Phone number — ต้องเป็น link เสมอ
```jsx
<a href={`tel:${phone}`} className="text-teal font-medium">{phone}</a>
```

#### Note / remark text — italic + quote marks
```jsx
<p className="text-base text-warm-500 dark:text-disc-muted italic">"{note}"</p>
```
